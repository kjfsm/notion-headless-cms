## バージョン整列方針: fixed mode 推奨

`.changeset/config.json` を以下に切替:

```json
{
  "$schema": "https://unpkg.com/@changesets/config/schema.json",
  "changelog": "@changesets/cli/changelog",
  "commit": false,
  "fixed": [["@notion-headless-cms/*"]],
  "linked": [],
  "access": "public",
  "baseBranch": "main",
  "updateInternalDependencies": "patch",
  "ignore": []
}
```

- fixed mode により全 `@notion-headless-cms/*` パッケージが常に同じ番号で公開される
- 利用者は「どれを入れれば良いか」を平易に判断できる (1.0.0 同期)

### 代替案

「core / notion-source / notion-orm のみ 1.0、他は独立 SemVer」も検討したが、
バージョン体系の混在 (現状 core 0.3.x / meta 1.0.x / fetch-* 0.0.x) を再生産する
ため非推奨。1.0 リリース時に fixed mode へ収束させる。

## 1.0-rc.0 リリース手順

1. 本ファイルのチェックリストをすべて ✅
2. fixed mode への切替 PR を作る:
   ```bash
   # .changeset/config.json を fixed mode に編集
   pnpm changeset add  # catch-up changeset (major) を作成
   ```
3. main へマージ → changesets/action が Version Packages PR を作成
4. Version Packages PR で `1.0.0-rc.0` がすべて揃っていることを確認
5. dry-run:
   ```bash
   pnpm install --frozen-lockfile
   pnpm build
   pnpm -r --filter="./packages/*" publish --dry-run --tag rc
   ```
6. `release-dry-run.yml` が PR 上で緑になっていることを確認
7. Version Packages PR をマージ → release.yml が `--tag rc` で npm publish

## 1.0.0 GA への昇格

`1.0.0-rc.N` で 2 週間以上の運用試験を経たのち、

```bash
pnpm changeset add  # bump 種別: minor (rc.N → 1.0.0)
```

で `1.0.0` Version Packages PR を作る。`--tag latest` で publish される。
