# v1 → v2 移行ガイド（sources API への移行）

v2 では module augmentation で拡張可能な `sources` API が導入された。CLI 生成物は DB 構造（`schema`）のみに専念し、ランタイム設定は `createClient` 側で組み立てる。

## 主な変更点

| 旧 (v1) | 新 (v2) |
|---|---|
| `createCMS` | `createClient` |
| `CreateCMSOptions` | `CreateClientOptions` |
| 生成ファイル `nhc.ts` | `nhc.schema.ts` |
| 生成物の `createCMS` ラッパー / `NhcConfig` / `Nhc` 型 | （廃止）`schema` 定数のみ |
| `createCMS({ notionToken, collections, ... })` | `createClient({ sources: { notion: notionSource(...) }, ... })` |
| `publishedStatuses` を生成物に埋め込み | `notionSource({ publishOptions })` 側で指定 |

## 必須インストールパッケージ

3 → 2 に減少。`notion-orm` / `renderer` は `notion-source` の `dependencies` として同梱される。

```bash
# v1
pnpm add @notion-headless-cms/core @notion-headless-cms/notion-orm \
  @notion-headless-cms/renderer ...

# v2
pnpm add @notion-headless-cms/core @notion-headless-cms/notion-source ...
```

## コード移行

### `cms.ts`

**旧 (v1):**

```ts
import { memoryCache } from "@notion-headless-cms/cache";
import { createCMS } from "./generated/nhc"; // 生成物の createCMS ラッパー

export const cms = createCMS({
  notionToken: process.env.NOTION_TOKEN!,
  cache: [memoryCache()],
});
```

**新 (v2):**

```ts
import { memoryCache } from "@notion-headless-cms/cache";
import { createClient } from "@notion-headless-cms/core";
import { notionSource } from "@notion-headless-cms/notion-source";
import { schema } from "./generated/nhc.schema";

export const cms = createClient({
  sources: {
    notion: notionSource({
      schema,
      token: process.env.NOTION_TOKEN!,
      publishOptions: {
        posts: { publishedStatuses: ["公開済み"] },
      },
    }),
  },
  cache: [memoryCache()],
});
```

### `notionSource()` のオプション

旧 `createCMS` のうち、Notion 固有のものは `notionSource` 側に移動した:

| 旧 `createCMS` の引数 | 新 |
|---|---|
| `notionToken` | `notionSource({ token })` |
| `collections.<name>.publishedStatuses` (生成物経由) | `notionSource({ publishOptions: { <name>: { publishedStatuses } } })` |
| `collections.<name>.accessibleStatuses` (生成物経由) | `notionSource({ publishOptions: { <name>: { accessibleStatuses } } })` |
| `blocks` | `notionSource({ blocks })` |
| `enrichers` | `notionSource({ enrichers })` |
| `ogp` | `notionSource({ ogp })` |

`createClient` に残るのは Notion 非依存のオプション (`cache` / `swr` / `renderer` / `imageProxyBase` / `waitUntil` / `hooks` / `logger` / `logLevel` / `rateLimiter` / `content` / `plugins`)。

### CLI 設定 (`nhc.config.ts`)

`output` のデフォルトが変わる:

```ts
// 旧
output: "src/generated/nhc.ts",

// 新
output: "src/generated/nhc.schema.ts",
```

`publishedStatuses` / `accessibleStatuses` は `nhc.config.ts` に書いても**生成物には埋め込まれない**。`notionSource({ publishOptions })` で指定する。

## 段階移行のヒント

1. `pnpm add @notion-headless-cms/notion-source`
2. `nhc generate` を再実行（生成物が新フォーマットになる）
3. `cms.ts` を上記パターンに書き換える
4. `pnpm typecheck` で残りのエラーを潰す

## 拡張ポイント — 自前のソースを追加する

`@notion-headless-cms/core` の `CMSSources` インターフェースを宣言マージすれば、`sources.<key>` を補完候補に追加できる。

```ts
// my-source/index.ts
import type { CMSAdapter } from "@notion-headless-cms/core";

declare module "@notion-headless-cms/core" {
  interface CMSSources {
    contentful?: CMSAdapter;
  }
}

export function contentfulSource(opts: { ... }): CMSAdapter {
  return { collections: { ... } };
}
```

利用側は `import { contentfulSource } from "./my-source"` するだけで `sources.contentful` キーが解禁される（Fastify プラグイン型拡張と同じパターン）。
